## Built to the v1.0.0 standard, not around it

The new suites were authored against `profiles/frontier-2026-07.yaml`, so they inherit
the same rules the existing corpus was upgraded to:

- Outcome, constraints, and an acceptance bar rather than numbered micro-steps. Ordering
  is kept only where it is externally mandated, and where kept, the reason is stated so a
  later pass does not strip it.
- Halts justified by consequence, not by uncertainty. Absent evidence is a soft gap;
  unreachable evidence is a hard halt.
- A declared parallel surface where a stage operates over independent items, with the
  aggregate step carved out.
- Output contracts that state the artifact set a complete run delivers, with a
  per-artifact depth standard.

Governance invariants are present throughout and were never softened.

## Quality measures

Machine-checked across the 276 new desks:

- 6,559 of 6,579 distinct paragraphs appear exactly once. The 20 that repeat are the
  suite workflow and halt blocks each desk carries by design.
- 122 labeled anti-fabrication guards, 122 unique, zero duplicates. Each is written to
  its own desk's failure mode rather than pasted, because identical boilerplate is the
  defect that rule exists to prevent.
- Zero em dashes, zero vendor names, zero unresolvable citations.
- 33,503 lines of desk content, median 117 lines per desk.

Domain vocabulary separates cleanly by suite: `workpaper` and `fieldwork` appear only in
GRC, `watermark` and `compaction` only in Data, `subledger` and `roll-forward` only in
Finance, `debarment` and `should-cost` only in Procurement, `shrinkage` and `occupancy`
only in Customer Support.

## Breaking: compatibility shims are retired

The shims introduced in v1.0.0 are **removed as of v1.1.0**. The pre-v1.0.0 names no
longer ship in any package, so anything still reading them must move to the current names.

| Was | Now |
|---|---|
| `references/codex-conservation-policy.md` | `references/handoff-density-policy.md` |
| `references/low-token-policy.md` | `references/handoff-density-policy.md` |
| `references/*-low-token-policy.md` | `references/*-handoff-density-policy.md` |
| `agents/openai.yaml` | `agents/<vendor>.yaml` |
| `continuity_packet.codex_handoff` | `continuity_packet.implementation_handoff` |
| `max_context_policy` | `context_policy` |

A continuity packet still using `codex_handoff` or `max_context_policy` now reads as
missing those fields rather than as an error, so migrate the key names when you next write
a packet.

Note the window this actually gave: v1.0.0 published on 2026-07-25 and v1.1.0 the same
day. If you are pinned to a v0.x release and relied on the old names, pin to
`v1.0.0`, which still carries the shims, and migrate before moving to v1.1.0.

## Release integrity

385 packaged skills, 385 checksum entries. Archives are deterministic: identical source
produces identical zips, so a mismatch means the content genuinely changed.

```bash
python3 tools/audit_skills.py
python3 tools/validate_sdlc_suite.py
python3 tools/validate_release_assets.py
```

## Packaging guard

The build now refuses to package a suite whose desk count is short of the roster declared
in its own `stage-contracts.md`, so a suite that is mid-authoring cannot ship as a partial
package. Skipped suites are named in the build output rather than silently dropped.
