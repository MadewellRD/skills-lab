# Skills-Lab v1.0.0

Status: published
Date: 2026-07-25

All seven Desk Suites move to v1.0.0 together, replacing seven version lines that had
drifted apart (web-dev 0.3.0, SDLC 0.2.0, everything else 0.1.0).

## Why 1.0.0

Two things became true in this release that were not true before.

**The vendor-agnostic claim is now literal.** Skill sources contain no vendor names. They
use `{{AGENT}}` and `{{CODING_AGENT}}` tokens resolved at build time from
`profiles/vendors/<vendor>.yaml`. The default build mentions no vendor at all, and the
audit fails if one leaks into a skill body. Before this release the repository stated the
goal while 144 hardcoded vendor references sat in the corpus.

**Model capability is versioned configuration rather than prose.** Every assumption about
the executing model lives in `profiles/frontier-2026-07.yaml`. A new frontier release is a
config change and a rebuild:

```bash
$EDITOR profiles/frontier-2026-07.yaml
for v in generic anthropic openai google; do python3 tools/build_skills.py --vendor $v; done
python3 tools/audit_skills.py
```

That reaches all 109 skills. `references/capability-baseline.md` is generated from the
profile and injected into every skill, so a profile bump propagates in substance rather
than only stamping a new version string.

## Architecture

Reference files were duplicated across packaged skills with no source of truth, and for
three suites they existed only as build output. They are now a three-tier cascade
resolved most-specific-wins: skill, then suite, then kernel. 725 duplicated copies became
277 source files, verified as a byte-identical reconstruction before the duplicates were
removed.

## Capability upgrade

Rebuilt against the frontier wave of 2026-05 through 2026-07, using the capability floor
shared by all reference models rather than any single vendor's ceiling.

- Numbered micro-steps became outcome, constraints, and an acceptance bar. Ordering was
  kept only where it is externally mandated and getting it wrong is unsafe, with the
  reason recorded so a later pass does not strip it.
- Halts retargeted from uncertainty to six consequence classes. Absent evidence is a soft
  gap; unreachable evidence is a hard halt.
- Token conservation became handoff density. At current context sizes the binding
  constraint is ambiguity, not volume.
- Stages over independent items declare a parallel surface, with the aggregate step
  carved out.
- Output contracts state the artifact set a complete run delivers instead of a menu.

Governance invariants were deliberately held fixed: never invent facts, separate fact from
assumption, preserve source hierarchy and conflicts, respect approval and
destructive-action gates. Capability raises the fluency of a wrong answer as fast as the
accuracy of a right one, so a more capable model is a reason to remove scaffolding and
never a reason to remove governance.

Compatibility shims ship for one release cycle and are removed in v1.1.0.

|---|---|---|
| `references/codex-conservation-policy.md` | `references/handoff-density-policy.md` | yes |
| `references/low-token-policy.md` | `references/handoff-density-policy.md` | yes |
| `references/*-low-token-policy.md` | `references/*-handoff-density-policy.md` | yes |
| `agents/openai.yaml` | `agents/<vendor>.yaml` | yes |
| `continuity_packet.codex_handoff` | `continuity_packet.implementation_handoff` | no |
| `max_context_policy: execution_packet_only` | `context_policy: relevance_density` | no |

## Release integrity

Archives are deterministic: sorted entries and fixed timestamps, so identical source
produces identical checksums. A mismatch means content actually changed. Previously every
rebuild changed every hash, which made checksum verification meaningless.

```bash
python3 tools/audit_skills.py
python3 tools/validate_sdlc_suite.py
python3 tools/validate_release_assets.py
```

Pre-v1.0.0 `CHECKSUMS-*-v0.1.0.txt` files at the repository root pin superseded releases
and are intentionally not validated against current packages.

## Tooling

`tools/cut_release.py` replaces five per-suite generate scripts that had drifted apart.
One command packages every suite, writes checksums and JSON manifests, generates release
notes, and regenerates `MANIFEST.md` from actual `dist/` state so the manifest cannot
drift from reality.
